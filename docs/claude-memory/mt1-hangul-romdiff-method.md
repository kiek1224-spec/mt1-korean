기록이 없는 빌드가 뭘 바꿨는지는 **롬끼리 바이트 차분**으로 되짚을 수 있다.
2026-09-12 에 v42~v50 아홉 버전을 이 방법으로 전부 복원했다 (`romdiff.py`).

**Why**: 이 프로젝트는 빌드로그 표에 CRC 만 남기고 산문 기록을 빠뜨린 적이 있다.
소스 주석에는 날짜가 달려 있어서, 차분(어디가 몇 바이트)과 주석(왜)을 맞추면 복원된다.

**How to apply:**
- **레코드 뱅크(`$10`~`$1D`)의 대량 차이는 잡음이다.** 메시지가 한 글자만 바뀌어도 레코드가
  통째로 밀린다. 진짜 신호는 코드 뱅크(`$00`~`$0E`, `$1E`, `$1F`)와 CHR 뿐이다.
- **`decode_tbl`(가나)로 읽으면 안 된다.** 한글은 정적폰트 1바이트 / `$BD <id>` 2바이트 /
  `$Dn` 공백이라 가나로 읽으면 뜻 없는 글자가 나온다. `static_font.txt` 로 디코드할 것.
- **2바이트 차이는 대개 텍스트가 아니라 `JSR` 주소다.** v43·v46·v49 가 전부 그랬다
  (`20 DF C3` -> `20 00 65` = `JSR $C3DF` -> `JSR $6500`).
- **정적 폰트에 음절을 추가하면 롬 전체가 다시 쓰인다.** 파생 변경이지 새 번역이 아니다.
  새 이스케이프 음절이 들어가면 그 뒤 id 가 전부 밀리는 것도 같다.
- 마지막에 **재빌드해서 CRC 가 목표 버전과 일치하는지 확인**한다. 일치하면 소스 트리가
  그 버전 상태라는 뜻이라 복원 결과를 믿을 수 있다.
